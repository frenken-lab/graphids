# Vehicle Graph Mamba Joint: shared behavior, vehicle context

## Goal and relationship to the current baseline

Build a **replacement candidate**, `vehicle_graph_mamba_joint`, that combines a verified parallel Mamba temporal block, an explicit graph neural network (GNN) over CAN IDs, a supervised attack classifier, and a normal-behavior anomaly scorer. Train on source vehicles and evaluate transfer to held-out vehicles. Measure complete-epoch throughput and detection quality against the existing event-level `temporal_hybrid` baseline. Make it the active software model after functional cutover, retaining the legacy Git revision and artifacts for reproducibility; evaluate the research replacement criteria below afterward.

The design addresses the **invariance–specificity tradeoff**: a shared behavior model can transfer but lose ID/payload detail; learned parameters tied to raw IDs can fit one vehicle but fail on another. The initial decision is **shared learned rules, bounded vehicle-specific normal context**. Mamba, GNN, and heads share weights across vehicles. A trusted normal reference supplies per-ID profiles, persistent nodes, and edges; these are data artifacts, not separately trained parameters for each ID. Explicit signal/DBC semantics, when genuinely available, are a separate privileged-information ablation. Never infer that equal numeric CAN IDs have equal meanings across vehicles.

This is a representation and objective change, not an exact acceleration of the baseline. Preserve the completed and running cross-vehicle fits as fixed comparisons. The current baseline has per-ID GRU memory feeding into a sequential `ssm_lite` event loop; its `mamba` option is unimplemented and it has no active GNN. Do not label `ssm_lite` or its custom kernel Mamba.

The design follows the graph and Mamba extension in [the audited plan](parallel-mamba-gnn-cross-vehicle-plan.md), but makes both the GNN and the joint classification/anomaly objectives required components of this model type. The relevant research pattern is shared/private representations and reference conditioning; domain invariance alone can discard predictive detail and has no guaranteed benefit over well-tuned pooled training. See [Domain Separation Networks](https://arxiv.org/abs/1608.06019), [DomainBed](https://arxiv.org/abs/2007.01434), and [the risks of invariant risk minimization](https://arxiv.org/abs/2010.05761). These works motivate experiments, not a demonstrated CAN result.

## Graph Mamba implementation evidence

Research update: 2026-10-13. The initial implementation remains a **spatiotemporal Mamba/GNN composition**. Mamba scans time within each keyed ID stream; the graph mixes contemporaneous streams. This choice preserves a meaningful causal scan order and shared parameters across different node counts. It is a proposed CAN architecture, distinct from reproducing a published Graph-Mamba model.

| Approach | Published mechanism | Implementation decision |
|---|---|---|
| [Graph-Mamba by Wang et al.](https://arxiv.org/html/2402.00789v1) | Local message passing plus a global Mamba scan over nodes, with degree-based prioritization and permutations. | Useful spatial baseline if local graph messages miss long-range relationships. Node serialization introduces ordering and tie-handling questions; numeric CAN ID order supplies no shared semantics. |
| [Graph Mamba Networks by Behrouz and Hashemi](https://arxiv.org/html/2402.08678v1) | Neighborhood tokenization, token ordering, bidirectional selective SSM encoding, and local encoding. | A possible spatial encoder control. Bidirectional scanning within a closed snapshot can be causal in physical time; bidirectional scanning over query time would leak future observations. |
| [STG-Mamba](https://arxiv.org/abs/2403.12418) | Spatiotemporal selective state modeling with a Kalman-filter-inspired graph module. | Architectural evidence for graph/SSM composition. Its benchmark results do not establish one jointly trained cross-dataset detector. |
| Per-ID temporal Mamba followed by bounded graph aggregation | Chronological scan plus same-cutoff relational readout, as specified below. | First CAN implementation: shared weights, explicit node identity, causal forecasting, and a graph ablation without altering the scan kernel. |

The released [STG-Mamba implementation at commit c885e56](https://github.com/LincanLi-X/STG-Mamba/blob/c885e5610263274f1141de78182c77d86b78c8e8/STGMamba.py) computes its selective recurrence with `for i in range(l)` and materializes time-by-channel-by-state coefficient tensors. Its input/output projections also depend on `args.features`. Reuse design ideas rather than copying that execution path: it does not meet this candidate's optimized time-scan or arbitrary-node-count requirements without redesign.

### Tensor operations and module boundaries

Keep snapshot features, reference context, node lifecycle, and the trainable encoder separate. A batch carries keyed stream segments and masks; a context carries immutable profiles and neighbor tensors; inference state carries caches keyed by `(capture, CAN_ID, generation)`, where generation changes on slot reuse. A storage slot must never inherit another ID's caches.

1. Project authorized node/bin features and context into `[B,T,N,D]`. Pack complete live stream segments into `[S,T_segment,D]`, where `S` counts real segments rather than possible CAN IDs. Run shared pre-normalized residual Mamba blocks along time. Unpack outputs with a recorded segment-to-node mapping.
2. Store bounded incoming neighbors as `[B,N,k]`, with edge attributes and masks. For each bin, gather sender embeddings, form edge-conditioned messages, reduce over valid neighbors, and apply a gated residual update to each receiver. Process time in graph-readout chunks if necessary. This chunks graph activation work, not the Mamba recurrence or its gradient history.
3. Pool only live nodes for classification; keep per-node forecast distributions and a global new-ID forecast. Losses and alert evidence use their own eligibility masks. Normalize incoming aggregation by valid neighbors so variable graph degree does not silently change scale.
4. Online, batch the live IDs' one-bin Mamba steps, run one graph readout, score the prior forecast against the newly closed bin, and produce the next forecast. Reset caches and pending forecasts on capture changes, eviction, and slot reassignment.

**State masking needs an execution policy.** A loss mask does not stop a standard Mamba block from advancing SSM or convolution state on zero-filled padding. A silent anchor is a real input that should advance; a transient before birth, after eviction, or during slot reuse is not. Initially group equal-length live segments for sequence training, split reused slots into distinct ID generations, and omit invalid prefixes entirely. Right-padding is acceptable for scored prefixes only if its resulting caches are discarded; carried caches must correspond to the last real token. In streaming mode step only real live streams. Do not assert identity updates for arbitrary masked tokens without implementing and testing both convolution and SSM semantics. Ordinary missing observations on a still-live transient are distinct from eviction.

### Hardware and backend gate

The V100 is [compute capability 7.0](https://developer.nvidia.com/cuda/gpus/legacy). The inspected official [Mamba build at e9594ce](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/setup.py) lists CUDA targets beginning at `sm_75`, without `sm_70`; [current Triton compatibility](https://github.com/triton-lang/triton#compatibility) lists NVIDIA compute capability 8.0+. These are concrete obstacles to assuming a stock current optimized V100 path. They do not prove that every historical or modified Mamba-1 CUDA build is impossible on V100.

Use **Ascend A100 as the initial development and benchmark target**, with **Cardinal H100 as an alternative and scaling target**. OSC documents [Ascend](https://www.osc.edu/resources/technical_support/supercomputers/ascend) A100 GPUs with 40 GB or 80 GB per device and [Cardinal](https://www.osc.edu/resources/technical_support/supercomputers/cardinal) H100 GPUs with 94 GB per device and four GPUs per GPU node. Start with one GPU; node-level aggregate memory is not one device's usable memory. These newer architectures remove the identified V100 architecture mismatch, while installed drivers, CUDA/PyTorch versions, dependencies, and the actual Mamba kernels still need verification. V100 portability is optional and does not block this replacement.

Make backend verification **the first implementation gate**, before the snapshot pipeline or full fit. On the selected A100 or H100, pin the Mamba and causal-convolution versions, then verify sequence forward/backward, optimizer, streaming step, cache semantics, peak memory, and throughput. Establish FP32 correctness, then compare BF16 and FP16 where the complete backend supports them. Use Mamba-1 as the reference architecture and benchmark Mamba-2 on the same workload before freezing the backbone; Mamba-3 is a later candidate. Choose by complete-pipeline cost and quality rather than generation number. Rerun the legacy baseline on the same GPU model for any architecture speed claim; preserve old Pitzer timings only as historical results.

The repository already records Cardinal and Ascend in `configs/resources/clusters.json`, and its Slurm renderer accepts cluster and GPU resource overrides. Before a pilot, refresh live partition/GRES information and identify the assigned GPU model and memory inside the allocation; the cached inventory is not evidence of current queue capacity or project eligibility. Use separate pinned environments per cluster when their system libraries differ. After single-GPU correctness and bounded batching pass, test multi-GPU data parallelism if full-epoch profiling justifies it; report scaling, global work per optimizer step, and total GPU-hours separately from single-GPU throughput.

At the inspected revision, [Mamba-1's fused forward](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/mamba_ssm/modules/mamba_simple.py) does not emit carried state, and [the selective-scan interface](https://github.com/state-spaces/mamba/blob/e9594ce1c732d97440f0332fdc43170a2294dbfa/mamba_ssm/ops/selective_scan_interface.py) explicitly excludes last-state gradients. First train independent windows with causal warm-up included in each sequence forward; evaluate continuous inference separately. Defer differentiable carry across training windows until a chosen implementation passes that exact contract. Pin the tested revision rather than installing moving `main`.

## Training across semantically different datasets

**Working hypothesis:** one shared behavioral backbone is viable across CAN datasets with different vehicles, ID meanings, and acquisition conditions. Its value must be demonstrated against separate models. Extending to other domains is a separate experiment that may share a backbone while requiring different input encoders, prediction distributions, and label heads.

There is relevant evidence beyond automotive data. [UniTS](https://proceedings.neurips.cc/paper_files/paper/2024/hash/fe248e22b241ae5a9adf11493c8c12bc-Abstract-Conference.html) studies a unified model on 38 datasets from multiple domains; its [official implementation](https://github.com/mims-harvard/UniTS) distinguishes joint training, few-shot adaptation, and special zero-shot configurations. [Moirai](https://arxiv.org/html/2402.02592v1) addresses varying frequencies, variable counts, and output distributions with multiple projections, permutation-aware variate interaction, probabilistic outputs, and balanced dataset sampling. These support heterogeneous training as an experiment; forecasting transfer is not evidence that a universal attack classifier or threshold will transfer.

### What can be shared

| Dataset difference | CAN first implementation | Broader-domain extension |
|---|---|---|
| Local node meanings | Namespace IDs by vehicle/capture; share functions applied to their behavioral features. No cross-dataset ID matching is required. | Define a meaningful node unit per domain, such as sensor or endpoint; supply observed node/edge types when known. |
| Feature schemas | One canonical CAN schema with provenance and availability masks; preserve raw payload and timing. | Schema-specific encoders project into a common width. Do not place sensor values and payload bytes in supposedly equivalent columns. |
| Sampling and units | Preserve seconds, exposure, and raw plus reference-relative timing. Source-select bin width by acquisition family when necessary. | Supply elapsed time, sampling interval, measurement type and units where available; use type-appropriate prediction heads. |
| Graph semantics | Vehicle-local reference dependence graph with generic zero-shot policy. | Use typed edges and domain-specific authorized construction policies; a communication edge and a sensor dependency are not interchangeable. |
| Targets | Shared binary attack head only for datasets with compatible, trustworthy event/interval labels. Forecast verified-normal observations. | Separate heads for incompatible tasks or label definitions; missing labels contribute no supervised loss. |
| Normality and threshold | Condition on immutable normal context; evaluate per-dataset alert calibration and exposure. | Share representation learning; keep likelihood families, score calibration, and alert policies explicit per task/access regime. |

A CAN ID can encode speed in one vehicle and status in another without preventing a shared timing/change model. However, the same byte-level pattern may be normal in one vehicle and malicious in another; the shared detector needs authorized context or observable distinguishing features. If identical available inputs require different labels and no permitted context distinguishes them, pooling cannot resolve the ambiguity. [Domain-adaptation theory](https://arxiv.org/abs/1901.09453) gives counterexamples and a tradeoff for invariant representations under label-distribution differences. Consequently, forcing all datasets into an indistinguishable feature distribution is not the initial training objective.

Use one fully shared CAN encoder/head stack first. Preserve schema and reference-presence metadata, but exclude learned dataset-name embeddings from the default held-out-dataset test. Compare metadata conditioning separately, with an explicit unknown-schema route. Small schema-specific input adapters or heads are valid multi-domain model variants; name them separately from the fully shared replacement and specify how an unseen schema is supported. An unseen dataset requiring a newly trained adapter is adaptation, not zero-shot transfer.

### Dataset compatibility and sampling contract

Before pooling, inventory each dataset's vehicle/session identity, acquisition source, clock units/resolution, payload serialization/validity, label ontology, verified-normal segments, attack generation, and preprocessing. Group reused vehicles and recordings across dataset names. The local registry lists HCRL variants and four CAN sets, but names alone do not establish independent datasets or equivalent labels. Freeze train/validation/test and reference permissions across the combined corpus; a held-out dataset cannot re-enter training through another dataset's alias or source session.

Sample hierarchically: dataset, vehicle, independent recording/episode, then a contiguous window. Initially give datasets equal probability and vehicles equal probability within each dataset; cap repeated exposure from small datasets and report sampling counts. Homogeneous-schema batches can alternate optimizer steps while sharing weights. Normalize each task loss by eligible units within an episode, then average episodes so high-rate or many-node datasets do not dominate. Record node-bin work, scored seconds, and optimizer contributions by dataset. Tune weights only on source validation, including a capped proportional-sampling control.

Keep sensor absence, no event, unobserved capture time, padding, and unavailable labels as different masks. A file with no labeled attacks is not verified normal merely because its label column is zero, particularly for suppression. Fit normalization from authorized training/reference partitions; never normalize a query using its complete future trajectory. Report source-only and reference-conditioned evaluation separately even when pooling improves average metrics.

### Experiments that decide whether pooling is useful

| Comparison | Question |
|---|---|
| Separate models versus fully shared pooled CAN model | Does sharing help each included dataset at matched evaluation and declared compute budgets? |
| Pooled model versus shared backbone with small schema adapters/heads | Is semantic/schema heterogeneity causing negative transfer that limited specialization resolves? |
| Leave one entire dataset/acquisition source out | Can it generalize beyond a held-out vehicle recorded by the same pipeline? |
| Train on A, on B, and on A+B; evaluate fixed validation partitions of A and B | Which dataset helps or hurts another, including low-data learning curves? |
| Normal-only pooled pretraining plus supervised source fitting versus joint training | Are transferable dynamics more useful than pooling attack labels? |
| Pooled Mamba-only versus pooled Mamba/GNN; self-only and rewired graphs | Does the graph add transfer value after accounting for model capacity? |

Run vehicle holdout within datasets and dataset holdout separately. For dataset holdout, select hyperparameters by rotating **source** dataset validation folds; preserve a final untouched dataset when the corpus supports it. Evaluate the same held-out queries with and without disjoint target normal reference, using the same checkpoint. Do not call an adapted dataset-specific head zero-shot. Begin with two source CAN dataset families after the compatibility audit, then expand only if the transfer matrix supports it.

Report per-dataset and per-vehicle false alarms/hour, episode recall, detection delay, AUPRC, coverage, and normal forecast calibration, with uncertainty over independent recordings. Attack prevalence affects AUPRC; pooled AUPRC cannot replace within-dataset comparisons. Show macro averages and the worst dataset, plus matched per-dataset exposure and a fixed-total-compute comparison; a pooled model trained longer than each specialist must disclose that advantage. Declare numerical noninferiority bounds on source validation before final tests. Pooling passes only if gains do not hide an unacceptable regression on an included dataset. A shared backbone with useful specialization remains a defensible outcome if full sharing fails.

## Replacement contract and decision rule

The replacement is a new **data representation, model, loss, and detector policy**. It does not inherit the old event-level input tensor, per-ID GRU state, `ssm_lite` weights, event target alignment, or checkpoint format. Reuse the experiment runner, recording manifests, provenance machinery, and common metric definitions where their semantics remain valid. Version the snapshot cache, vehicle context, model checkpoint, score alignment, and alert policy independently. A legacy checkpoint must fail a new-model load explicitly. Keep the old model runnable until the new system passes the acceptance gate; this is a migration safety measure, not a second active architecture in the replacement.

The deployed detector's unit is a **closed physical-time bin**. It emits a timestamped classifier score, a forecast surprise score aligned to that same bin, component scores, and an alert decision under a frozen policy. It also emits coverage and lifecycle counters (observed IDs, silent anchors, transient overflow/evictions, unavailable payload fields, and warm-up). Define an exact mapping from bin alerts to attack intervals and event labels before comparing with the legacy event detector. A bin containing one attacked event is a positive bin for classification, but that rule cannot establish event localization or suppression recall. An alert's earliest possible time is the bin close plus measured computation latency; include binning delay in detection latency.

Predeclare replacement acceptance on **source validation**, then confirm once on untouched target test recordings. At minimum require: valid split/provenance and causal-equivalence gates; complete scored coverage; a functioning optimized Mamba training and streaming path on the selected Ascend A100 or Cardinal H100; a measured full-fit resource budget; and classifier and anomaly results reported separately under the same alert-time and false-alarm-hour policy as baselines. Set numerical quality, latency, memory, and throughput bounds from the completed baseline and source pilot **before** target attack tests. A speed win cannot compensate for an unacceptable low-false-alarm detection regression, and an anomaly head that adds no useful detection should not be described as a successful joint replacement. If official Mamba cannot pass the hardware gate, stop this named candidate or explicitly rename and evaluate a different temporal backbone; never silently substitute `ssm_lite`.

Evaluate **both transfer regimes as co-primary experiments** with the same shared checkpoint, held-out query recordings, score coverage rules, and alert metrics: (1) source-only zero-shot, with no target normal data or target graph; and (2) target-normal-reference-conditioned, with an immutable context built from disjoint trusted normal recordings and no weight updates. Predeclare both before fitting and report paired per-vehicle differences, reference construction cost, and reference duration sensitivity. Keep threshold access as a separate experimental axis: the primary paired comparison uses source-selected thresholds in both regimes; a target-normal-calibrated threshold is an additional conditioned result using a third, disjoint normal capture partition. A source-only model cannot infer expected silent target IDs without an authorized target specification, so suppression claims in that regime need direct evidence and appropriate interval labels.

## Decisions and remaining gates

| Question | Initial decision | Evidence needed before freezing it |
|---|---|---|
| What generalizes? | Shared behavioral, temporal, relational, and detection weights; no default learned raw-ID or vehicle embedding. | Compare pooled behavior-only, reference-conditioned, and ID-specific controls on source-held-out vehicles. |
| What is vehicle-specific? | Frozen normal profiles and graph, built from disjoint authorized captures. | Measure reference duration sensitivity, context-swapping failure, and construction cost. |
| How are shared and specific parts trained? | One shared Mamba/GNN/head stack trained on source-vehicle reference/query episodes; each episode supplies its own fixed normal context. No default vehicle-specific weight branch. | Compare shared-only, fixed-profile conditioning, and learned-reference conditioning at matched data and compute. |
| How is zero-shot supported? | Include a declared fraction of source episodes with reference context withheld and the same generic graph policy used at zero-shot test time. | Verify that context-available and context-absent validation both remain useful; tune this fraction on source validation. |
| How are transfer regimes compared? | Freeze one checkpoint and paired target query sets; run zero-shot and normal-reference-conditioned paths with source-selected thresholds as co-primary results. | Verify target reference and query disjointness, identical scored time, and sensitivity to reference duration; report per-vehicle paired effects rather than only pooled scores. |
| Which IDs persist? | Every distinct ID in the authorized normal reference is an anchor up to a declared capacity ceiling `K_max`; `M` separately bounds distinct query-only transient IDs. Neither budget is an attack label. | Audit reference-to-query normal coverage, attack/transient load, and GPU memory before choosing `K_max` and `M`. The repository's 8,192 local-ID capacity is not an observed count. |
| How are anchors selected? | Use reference-set membership, not frequency ranking, while the distinct-ID count fits `K_max`; freeze membership during each query. | If a reference exceeds capacity, fail context construction or apply a predeclared source-validated overflow policy and report excluded IDs. Do not use target attack labels to choose anchors. |
| What is zero-shot? | No target normal profiles, persistent-ID expectations, or target graph. Use shared weights and a generic causal graph policy. | Report separately; strong unseen-ID suppression detection cannot be claimed without an expected-ID reference or another authorized specification. |
| What is the anomaly task? | Self-supervised forecasting trained on known-normal source segments, sharing the encoder with supervised classification. | Test loss interference and anomaly-only performance; tune weights on source validation. |
| What is the prediction unit? | Physical-time bin; classify the just-closed bin and forecast the next one. | Choose bin width from source data, quantify event-to-bin label dilution and detection delay, and compare common alert-time metrics with event baselines. |

The [normal-anchor audit](docs/empirical-notes/2026-10-03-vehicle-graph-mamba-data-audit.md) establishes per-file and per-vehicle normal ID unions and shows that all-reference-ID anchoring is feasible by node count in these files. The next pass must count attack/transient load, candidate graph density, missing expected bins, and memory/activation scaling in `K_max`, `M`, `T`, and width `D`. This is necessary before assigning numeric defaults to the capacity ceiling, `M`, or bin width.

## Model contract

```text
CAN recordings
  -> disjoint vehicle/capture splits and causal physical-time bins
  -> all trusted reference IDs as frozen anchors (up to K_max) + up to M distinct transient IDs
  -> observed per-ID features and authorized reference context/graph
  -> shared official Mamba block along time for each ID, trained in parallel
  -> sparse same-time GNN across IDs at each bin cutoff
  -> attack classification head + next-bin normal-behavior heads
  -> separate classification probability and calibrated anomaly score
```

The first implementation uses a physical snapshot grid rather than treating the kth event of each ID as simultaneous. A bin becomes available only after its cutoff. Inputs at cutoff `t` may use observations through `t`; forecast heads predict bin `t+1`. A bin with no message is an observed zero-count bin, not padding. This permits suppression to appear as an anomaly through count and increasing age.

### Inputs and provenance

Split vehicles and whole recordings before constructing windows, normalization, profiles, or graph edges. Maintain disjoint source train/validation captures and separate held-out target **normal reference**, **normal threshold calibration**, **normal test**, known attack, and unknown attack captures. The current cross-vehicle source exposes calibration and normal-test partitions; this model needs a further recording-level reference/calibration split before using both services. Do not build a graph from the same normal files used to set its alert threshold and then call those files an independent calibration set. Record the files and time ranges used for every derived artifact.

For each vehicle, capture, time bin, and local CAN ID, compute only causal observed features: message count, latest payload bytes/bits, available-byte mask, payload-change summary, arrival-gap summary, age since last message, and observed/missing flags. If true DLC/valid-byte metadata are unavailable in a source, mark that provenance explicitly; do not fabricate a validity mask from zero-filled bytes. Include time/boundary, `in_reference`, and `new_id` flags. Add optional causal same-ID timing features from the existing behavioral representation. Do not assume payload bytes are decoded physical signals. Fit numeric normalization only on authorized training or reference data; freeze it for each query sequence. Preserve the raw numeric ID as an optional arbitration-priority feature ablation, not a shared semantic token.

Represent a batch as `X: [B,T,N,F]`, with real-node, time, payload-availability, and target masks. For the first eager implementation, pack only real ID streams where possible; pad time tails or mixed-vehicle batches only as required by a tensor operation. Mask any padding from graph edges, pooling, losses, and scores, and verify that padded streams cannot affect real Mamba outputs or carried state. Reference anchors retain their identity across captures of the same authorized vehicle profile, keyed by raw CAN ID (and channel if present). Transient local indices are only storage slots: maintain a keyed mapping so two distinct IDs never share a live slot, and never treat slot number as semantics. Do not use a cross-vehicle ID identity or a learnable vehicle ID embedding.

### Snapshot batching and memory contract

The historical `snapshot_sequence` GAT materialized multiple disconnected graphs into one variable packed batch; a failed V100 run reached about 58,000 nodes and 183,000 edges ([audit](docs/empirical-notes/2026-05-31-gat-snapshot-sequence-v100-illegal-memory.md)). Its illegal-memory failure was traced to a manual self-loop rewrite, **not** batch size, but the workload shows why node and edge budgets must be explicit. The later temporal CUDA Graph path succeeded because eligible lane batches had stable geometry and irregular batches fell back to eager execution ([throughput note](docs/empirical-notes/2026-09-29-temporal-lane-throughput-check.md)). The new snapshots can recreate variable packed shapes if implemented as arbitrary PyG graph batches. Do not use dynamic whole-graph packing or per-batch CUDA Graph capture as the first training design.

Budget **node-bin tokens** `B*T*(K_actual+M_active)` and **graph messages** `B*T*E_t`, not just the number of CAN IDs or windows. For scale, `B=4`, `T=128`, and 160 slots already mean 81,920 node-bin tokens; an eight-neighbor cap permits up to 655,360 directed messages. These are workload counts, not proposed defaults or measured memory. Mamba activations, graph gather tensors, backward storage, optimizer state, and prefetch can multiply their footprint. A low ID cardinality alone does not make a snapshot batch cheap.

First implementation: fixed bin width and bounded sequence length selected on source data; eager batches with the actual number of anchor and live transient streams where practical; fixed per-node neighbor cap (or a bounded sparse edge list with a deterministic cap). Build contiguous capture-local windows, keep anchors present through silent bins, and use masks for unavailable nodes, partial terminal bins, edges, and targets. A silent anchor is a **real zero-count observation**, whereas a padded node/time has no state or loss. Keep actual `B`, `T`, `N`, edge count, and any padding visible in the batch manifest. Allocate batches by a conservative upper bound on node-bin and message work; never estimate solely from event count or average graph size. Overflow must follow the documented transient policy, never an unlogged truncation of a large batch. If the observed geometry exceeds a configured limit, fail with a coverage report; introduce causal window splitting only after state-carry semantics are verified. Test a small number of node-capacity buckets only if eager variable-shape execution shows a measured throughput benefit that outweighs padding.

Do **not** materialize a PyG `Data` object or separate CUDA execution graph for every time bin. The reference anchor topology is one immutable neighbor-index/weight tensor per vehicle context, broadcast across `T`; node features and missingness change over time. Query-derived transient links use bounded neighbor slots and masks whose **values** can change at each cutoff without changing tensor shapes. Implement the graph readout as a batched tensor operation over `[B,T,N,D]` (or time chunks of that tensor under the same capacity bounds). Compare fixed-neighbor gather with a small dense-adjacency operator on source workloads: fewer than 100 anchors may make dense execution simpler, but its `N²` activations can be costly. The graph operator must not rebuild a disconnected sparse graph for every bin. If the zero-shot causal edge policy cannot be expressed within bounded slots and acceptable construction cost, simplify that policy before claiming a fast shared model; do not hide dynamic graph construction in the dataloader.

Use eager execution first with the official optimized Mamba sequence kernel. Eager batches may have different actual `N` and edge counts; a new tensor shape does not create a saved CUDA execution graph. CUDA Graph capture is an **optional later optimization** only after full-fit memory and correctness gates. If tested, capture at most a small, predeclared set of fixed `(B,T,N,edge-capacity)` shapes with stable input/state storage and tensor-valued masks; impose a hard capture-cache memory limit. Partials, unusual overflow, and unsupported shapes run eager rather than creating a new capture. Do not assume PyG scatter/edge operations become graph-safe merely because tensors are padded. Compare replay and eager scores, gradients, state, and coverage across empty bins, silent anchors, transient churn, and capture boundaries.

Before the first full fit, run a source-only workload census for candidate bin widths and window lengths: p50/p95/p99/max nodes, node-bin tokens, active and padded transient slots, edges/messages, empty bins, and attack-containing bins. Then preflight the worst permitted geometry on the selected A100 or H100 with warmed-up forward, backward, optimizer, and dataloader prefetch; record allocated/reserved/NVML peaks and complete-epoch throughput. Use this evidence to set `B`, `T`, `K_max`, `M`, neighbor cap, and a memory headroom rule. The acceptance gate is complete coverage without shape-driven capture proliferation or out-of-memory failures, not a successful average batch.

For the graph, start with a fixed sparse directed graph **among all authorized reference anchors** inferred from normal reference traffic using lagged activity and payload-change dependence. `K_max` bounds nodes; a separate neighbor cap bounds edges. Store edge direction, weight, lag, and reference provenance; distinguish statistical dependence from physical causality. Keep anchor nodes present through zero-count bins so their missingness can be scored. Active non-anchor IDs enter as distinct transient nodes with a shared generic profile, self path, and optional bounded edges to anchors derived only from observations available by the current cutoff. Their absence from the reference is not itself an attack label or automatic anomaly. Specify overflow and eviction (for example, least recently observed after a minimum retention horizon), expose eviction counts, and do not let query traffic promote transient IDs into the frozen reference graph. Test adversarial flooding of transient slots.

Reference-derived graph and profiles remain fixed during a query sequence. State three regimes precisely: **zero-shot** uses no target normal data, no target reference graph, and source-selected thresholds; **normal-reference-conditioned** uses disjoint target normal captures to build profiles/anchors/graph, with frozen model weights; **target fine-tuning** changes weights and is a separate experiment. Target-normal threshold calibration is another explicit choice and must be reported separately from context construction. A zero-shot generic graph may capture current activity relationships but cannot know that a never-observed target ID should have appeared. Neither transfer regime may use target attack labels to construct context or select architecture.

### Parameter sharing and source-vehicle episodes

Use **one shared parameter set** for the input projection, Mamba blocks, graph message and update functions, reference-context encoder if enabled, classifier, and forecasting heads. No per-vehicle expert, learned ID table, or separate classifier is required in the first model. The vehicle-specific object is a versioned `VehicleBehaviorContext` containing reference provenance, anchor IDs, normal profiles, normalization, and graph. Its values are fixed while a query sequence is scored. A learned reference encoder can be trained across source vehicles, but its weights are shared; recompute encoded context after encoder updates and never let query attack traffic update the reference artifact.

Build training episodes by choosing a source vehicle, then disjoint normal **reference** captures and labeled **query** captures for that vehicle. Construct profiles, anchors, normalization, and graph only from the episode reference; use the query for classification and verified-normal forecast targets. Rotate permitted reference/query captures across epochs without letting a query capture become its own reference. Balance source vehicles at the episode sampler or loss aggregation, and report the sampling weights. Keep capture chronology and all source-validation recordings separate from source training.

For a declared fraction of source episodes, withhold vehicle reference context and use exactly the generic node/edge policy intended for zero-shot inference. This trains the same shared weights in both access regimes without giving the model a target graph at zero-shot test time. A context-present flag must be explicit. Do not drop individual graph edges at random and call that zero-shot: the absence of the whole reference changes node identity, expected-missing behavior, and graph construction. Select the context-withholding fraction and any balance between regimes on source validation only.

Start with deterministic normal profiles and fixed reference edges to establish a clean baseline. If conditioning helps, add a shared learned reference encoder and train it jointly through source reference/query episodes; the reference input remains disjoint and fixed within an episode even though gradients update the encoder between optimizer steps. A normal-only pretraining stage for Mamba/reference features is an optional source-validated initialization, followed by joint classification and forecasting. Do not require separate pretraining and fusion for the first result. If joint losses interfere, compare alternate loss weights or staged initialization while holding the data split and total training budget explicit.

Treat a shared-plus-one-expert-per-vehicle design as a **specialization control**, not the default architecture. An unseen target has no trained branch, so its routing/fallback rule must be specified and evaluated independently; a source-expert mixture cannot be assumed to transfer. A small adapter trained from target normal data is a later **adaptation** experiment with a separately reported training cost, frozen/shared backbone policy, and no target attack labels. If experts are later justified, first test shared experts for behavioral regimes with a generic fallback rather than binding experts to vehicle names.

### Parallel temporal block

Project each node/bin token, observed timing features, optional reference node context, and optional vehicle context into width `D`. Pack as `[number_of_real_ID_streams,T,D]`. Run one or more shared **official Mamba blocks** forward in time with causal convolution and token-wise normalization. The block's selective state update may be recurrent mathematically, but full-sequence training must use the backend's optimized parallel path. Feed physical elapsed time as a feature; do not treat Mamba's learned step size as calibrated physical time. Persistent anchors have a sequence of real zero-count bins even when silent. Transient IDs begin at their first observation; cold-start state, preceding-window absence, and any eviction reset must be explicit and reproduced in training.

There is **no per-ID GRU memory read/write loop** and no learned output from an earlier query bin is injected into a later Mamba input. The Mamba block itself provides dynamic temporal state; the frozen reference profile provides longer-lived vehicle expectations. The graph stage receives completed Mamba outputs and does not feed back into that same temporal block. It also keeps the memory cost bounded by the active `K_actual + M` streams (`K_actual` is the authorized reference's distinct-ID count, at most `K_max`) rather than allocating learned state for every possible ID and lane; measure actual savings, since activations and snapshot padding can still dominate.

Pin the official Mamba implementation version/commit and verify import, CUDA kernels, forward, backward, mixed-precision behavior, peak memory, and full-fit speed on the selected A100 or H100 target. A successful import alone does not establish parallel training. Keep a clearly labeled reference or diagnostic fallback, never a silent slow production fallback. Verify both SSM and causal-convolution cache handling for streaming inference; support chunked training only after testing the selected backend's initial/final-state and gradient semantics.

### Bounded training windows and continuous inference

Training may use bounded physical-time windows for parallel Mamba forward/backward and a bounded graph readout. Inference may score an arbitrarily long **continuous recording** one closed bin at a time without storing its full history: retain each live ID's Mamba SSM state and causal-convolution cache, the last observed payload/timestamp and bounded causal feature state, the immutable vehicle context/anchor topology, transient slot mapping, and alert-policy state. The graph layer above is a same-cutoff readout and has no recurrent graph state of its own. Thus the inference state size depends on `K_actual + M` and model width, not the number of elapsed bins. A long-running process still needs explicit capture/vehicle resets and a trusted context-refresh boundary; "unbounded" means duration, not unlimited IDs, raw history, or guaranteed long-range recall.

Finite-state inference is mathematically possible beyond the training window, but quality is **not guaranteed** beyond the histories seen during training. A model trained only from zero state on short windows may learn startup behavior and fail after hours of state evolution. Select training window length and warm-up history from source data; use varied causal starting positions, a declared amount of unscored warm-up within the training budget, and a declared reset/cold-start distribution. Preserve complete continuous validation recordings to expose drift. Do not periodically reset inference merely to make it match training unless that reset is an explicit detector policy evaluated for missed attacks and false alarms. Cap/saturate age and count features using source-derived ranges so long silences do not produce uncontrolled numerical extrapolation, while retaining an explicit "beyond cap" flag.

The first backend gate must compare one full-sequence forward with bin-by-bin `step` outputs and final **both** SSM and convolution caches, including lengths longer than the training window, empty bins, transient starts/evictions, and capture resets. A full-sequence training kernel does not automatically provide gradient-correct state carry across successive training windows. Do not claim truncated backpropagation through windows until the pinned implementation supports and passes initial/final-state and gradient tests. If long continuous validation reveals a material train/inference mismatch, lengthen source training windows, add verified stateful chunk training, or define a source-validated finite horizon; do not infer long-horizon quality from the existence of a recurrent cache.

### Same-time graph layer

Reshape Mamba outputs to `[B,T,N,D]`. At each completed physical cutoff, apply a small sparse message-passing GNN across persistent and live transient IDs using the authorized anchor graph and causal transient edges. Edge features may include direction, weight, lag, and observed age. Apply the same batched operator independently to each `(vehicle, time)` slice with no messages across vehicles or times; reuse each vehicle's reference topology across its time axis rather than constructing a graph object per slice. Use a residual self path and one graph layer initially; increase depth only if source validation shows a gain. The GNN uses the state available at that cutoff and cannot see the next bin. A static edge remains an expectation even when one endpoint is silent; graph messages must carry observed/missing information rather than implying a message arrived.

**First architecture choice:** input projection -> **two shared causal Mamba blocks** along each ID's time axis -> **one directed, edge-aware gated message-passing layer** at each cutoff -> masked per-ID/global heads. Two Mamba blocks and one graph hop are provisional source-preflight settings, not a claim of optimal depth. Keep width and state size within the selected device memory gate. Do not run Mamba and GNN as independent parallel branches in the first model: a raw-input graph branch would not give relational messages access to the ID's learned temporal state, and its extra fusion path would obscure the graph ablation. A full graph-before-Mamba or alternating design remains an error-driven follow-up for cross-ID lag.

Use a GraphSAGE-style shared neighbor aggregator with learned edge-conditioned messages and a gated residual update, rather than starting with multihead GAT. For each directed edge `j -> i`, form a message from `h_j,t`, the observed/missing and age features, and the frozen edge's direction/strength/lag; normalize or gate the bounded incoming messages, then update `h_i,t` through a learned projection plus residual self path. Keep self transformation separate from neighbor messages. This supports inductive shared weights, edge provenance, silent anchors, and bounded neighbor tensors. It avoids the old GATv2 self-loop rewrite path and gives a clean self-only control. Attention, learned edges, or a second message-passing layer require a measured source-validation gain at matched inputs, width, and compute. Two graph layers expand to two-hop relations and increase activation/message cost; they may also wash out rare-node signals. A one-layer graph can already combine temporally encoded states from directly related IDs.

This layer is required in the full model, not merely a graph-shaped input. Measure its contribution using a **Mamba-only ablation with the same inputs, width, heads, and training budget**, plus an edge-removal/rewiring check. Do not equate a larger parameter count with a relational gain.

Freeze the first architecture search to a compact source-only matrix: one versus two Mamba blocks at the same width; zero (self-only) versus one graph layer at the selected temporal depth; a second graph layer only if one-hop error analysis identifies missed two-hop relationships. Compare edge-aware aggregation with a parameter-matched plain weighted neighbor sum; test learned attention only if fixed-reference edges fail to adapt across normal modes. Run graph-before-Mamba only if cross-ID lag errors persist after the first ordering. Use the same binning, context, heads, splits, score policy, and optimizer/work budget in each ablation; avoid a broad depth/ordering search on three target vehicles.

### Representational gaps and candidate orderings

The first `Mamba -> GNN` design gives each ID its own temporal history, then mixes ID states at each physical cutoff. It does **not** explicitly carry a history of graph messages or guarantee that a short cross-ID sequence is represented. Before adding layers, measure three possible failure modes:

1. **Cross-ID lag:** an abnormal relationship may be a sequence such as ID A changing and ID B responding late, not a same-cutoff difference. Test whether lagged edge features and each node's temporal state recover it; inspect errors by lag and relation type.
2. **Event resolution:** a brief injection or precise arbitration order can disappear inside a physical bin. Compare source-selected bin widths and an event-resolution control; report detection delay and label dilution, not only bin classification accuracy.
3. **Operating-mode variation and payload semantics:** normal schedules and payloads may shift with vehicle mode, while a payload manipulation may preserve timing and graph structure. Check false alarms by normal capture/mode where metadata permit, and report timing-only versus payload-aware results. A learned graph is not a substitute for payload modeling.

Keep the data contract, graph construction, heads, splits, and alert metrics fixed while testing temporal/graph order. Candidate configurations are:

| Candidate | Question it tests | Added cost or limitation |
|---|---|---|
| Per-ID Mamba `->` same-time GNN | First model: can temporal states plus one relational readout detect the target attacks? | Cross-ID lag is indirect. |
| Observation-only GNN `->` Mamba `->` GNN | Does giving each ID current, causal neighbor observations *before* temporal encoding help? | More graph work. The first GNN reads observed features at each cutoff, not earlier model outputs; it is computed for the full sequence before Mamba so training remains parallel across time. |
| Alternating graph and temporal layers | Does richer temporal-relational interaction add quality after the simpler orderings? | Larger activations and full-fit cost; do not introduce until the first two orderings have evidence. A completed graph layer may feed a later temporal layer, but no graph output may feed backward into the same layer's prior time step. |
| Event-level dynamic graph control | Is information lost by snapshot bins? | Event-level memory models can reintroduce serial updates; label the execution path and measure it separately. |
| Causal TCN `->` same-time GNN | Does Mamba's long temporal state improve quality or cost over a simpler parallel encoder? | Finite receptive field; match its effective history and parameter/compute budget as closely as practical. |

These are experiments, not claims that one ordering is better for CAN. The spatial-temporal alternatives are motivated by [Graph WaveNet](https://arxiv.org/abs/1906.00121) and [DyG-Mamba](https://arxiv.org/abs/2408.06966); event-level memory models by [Temporal Graph Networks](https://arxiv.org/abs/2006.10637); and the convolutional control by the [TCN comparison](https://arxiv.org/abs/1803.01271). A [CAN relational study](https://www.mdpi.com/1424-8220/26/10/2964) illustrates why structural timing features alone may miss timing-preserving payload manipulation. None of those papers establishes performance for this exact data and split.

## Physical structure and vehicle-generalized behavior

Do not call the first model a **physics-informed neural network** merely because Mamba has a state. Mamba's learned state is a compact history of inputs, not a measured physical state with known vehicle equations. The local can-train-and-test CSVs expose timestamp, arbitration ID, payload hex, and attack label, but no verified DBC signal layout, vehicle speed, acceleration, torque, gear, actuator input, bus bitrate, or independent sensor measurements ([data audit](docs/empirical-notes/2026-10-03-vehicle-graph-mamba-data-audit.md)). A PINN-style dynamics residual would require observable or credibly inferred physical variables, units, and governing equations. Imposing a guessed speed/RPM equation on opaque bytes could manufacture false alarms and misleading cross-vehicle alignment. [PINNs](https://arxiv.org/abs/1711.10561) use known equation residuals; [CAN-D](https://arxiv.org/abs/2006.05993) shows that recovering CAN signal boundaries and physical interpretation is itself a separate inference problem.

Use three evidence levels and name them accurately:

1. **Protocol/behavior informed, first model:** represent real elapsed time, per-ID periodicity and jitter, zero-count bins, arrival order, payload availability/change, and bounded directed lagged relationships learned from trusted normal reference. These are observable CAN behavior, not laws of vehicle motion. Use source-selected plausibility/regularity features and proper forecast scores; never declare a normal operating-mode change physically impossible merely because it is rare in the reference.
2. **Latent role learning, source-validation ablation:** train a shared encoder of each ID's causal rhythm, payload-change pattern, and relation neighborhood; optionally compare source-derived role prototypes or contrastive consistency across disjoint normal captures. Condition the graph/forecast heads on these **behavioral roles** while retaining local ID keys for state and missingness. Require ID-permutation equivariance and compare against the same model without role features, shuffled roles, and context swaps. A similar role does not establish that two raw IDs encode the same physical signal; do not use target attack labels to align roles.
3. **Verified physical-signal experiment, only if new evidence exists:** with trusted DBCs or validated decoding plus independent signals/units, add a separate head or soft residual for specific checks such as speed/acceleration continuity or agreement among speed, RPM, gear, and actuation. Express the equation, sampling alignment, measurement uncertainty, and operating regime explicitly; mask it when required signals are absent. Compare with identical architecture without the residual and report the extra privileged information. It is a different access regime from raw-CAN transfer, not a hidden requirement of the main model.

This ladder can steer vehicle generalization through **shared behavioral relationships**—for example, "regular periodic stream whose payload changes after another stream"—without equating arbitration IDs across vehicles. The frozen target normal reference supplies local expected schedules and edges; the shared encoder learns which kinds of timing/payload/relational deviations matter. If verified decoded signals later exist, physical constraints may supply stronger semantic alignment, but that cannot be claimed from opaque payloads alone. A [CAN-D study](https://arxiv.org/abs/2006.05993) illustrates the decoding gap; a [physics-guided EV intrusion study](https://trid.trb.org/View/1874926) uses additional power-electronics and vehicle-dynamics models, which are not present in these CSVs.

### Discovering candidate roles and signal-like fields

The repository already has `graphids/core/data/discovery/hypotheses.py`. Its current `build_signal_profiles` groups **whole arbitration IDs** and records message count, IAT mean/std, byte mean/std/range, and change rate; `initialize_hypotheses` creates empty candidate mapping rows. It does not locate bit-field boundaries, decode endianness/signedness, establish physical units, or verify semantic labels. Its timestamp difference is taken after sorting/grouping by vehicle and ID but not capture, so concatenated recordings can create artificial interarrival gaps at capture boundaries. The current loader also zero-fills absent payload bytes; those byte summaries must not be treated as measurements until raw length/validity provenance is preserved. `attack_max` and `attack_rate` in a discovery artifact would leak attack labels if used to build target context. Treat this module as a scaffold, not an existing cross-vehicle signal mapper.

Use a **preprocessing-first, uncertainty-preserving** pilot before adding end-to-end alignment to the detector:

1. On permitted **normal-only reference captures**, profile each `(vehicle, capture, ID)` separately: period/jitter, burstiness, payload length, per-bit toggle and run-length behavior, candidate counters/checksums, and relationships to other candidate streams under causal lags. Aggregate across captures only after preserving capture/mode variance and raw provenance.
2. Generate candidate **bit fields within an ID**, including alternative contiguous boundaries and byte order where supported. A message can contain several physical signals plus counters/status bits; a whole ID is not necessarily "the speed signal." Keep candidates and confidence, including `unknown`, rather than forcing a single decoding or one-to-one cross-vehicle match. CAN-D's staged boundary/endianness/signedness method motivates this separation; it obtains physical interpretation for only a subset through diagnostic information ([CAN-D](https://arxiv.org/abs/2006.05993)).
3. Compare candidates by scale-robust temporal shape, smoothness, periodicity, value transitions, operating-mode dependence, and graph-neighborhood role. Cluster or softly match candidates across **source vehicles** with an unmatched option; validate stability across disjoint normal captures and leave-one-source-vehicle-out. Do not use common numeric IDs, absolute byte values, file names, attack labels, or target query recordings as matching evidence. Earlier work reports learnable statistical features for cross-vehicle signal extraction, but similarity is a hypothesis until independently checked ([cross-vehicle extraction study](https://arxiv.org/abs/1902.08956)).
4. Version a sidecar of candidate fields, role probabilities, confidence, raw bit ranges, capture hashes, and method settings. The first model integration is a **soft role/context feature** added to the frozen reference object while retaining original ID and raw-byte features; low-confidence candidates fall back to generic behavior. Compare no-discovery, whole-ID profiles, field-aware roles, and shuffled roles at matched compute and target access. Only promote a role to a name like "speed" when a DBC, diagnostic PID, independent sensor, or documented controlled maneuver validates its semantics.

An end-to-end role learner is a later option after the sidecar pilot establishes a signal. It must derive target roles from the trusted normal reference alone and keep them fixed through attacked queries, or the model could adapt its role assignment to the attack. It must also retain an unmatched/uncertain state and pass ID-permutation tests. The primary research outcome is improved transfer and interpretable **behavioral role consistency**; accurate vehicle-signal naming is a separate claim requiring external ground truth.

### Mining recurring graph behavior

The fixed reference adjacency is a candidate-dependence map, not a fresh graph inferred independently in every bin. Mining static triangles or degree patterns from that same map would mostly restate its construction rule. Instead, use the causal node observations over bins to form **activity- and change-weighted temporal patterns** on the bounded reference graph: directed pairs with a consistent lag, three-stream chains or converging changes, repeated co-activity, and the expected silent/active transitions of neighboring anchors. Keep edge type, lag, support, and observation masks; a missing message is informative for an expected periodic anchor, whereas an unobserved or padded node is not.

Here **two or three streams means distinct participating IDs/fields, not consecutive messages or a limit of two or three events**. For example, `A -> B -> C -> A` uses three streams and four qualifying changes; unrelated traffic may occur between every step. Define each arrow by an observed change in the destination after an observed change in the source within a source-selected lag interval, with an overall maximum span and a rule for overlapping matches. Use event timestamps or sufficiently fine bins for order; changes in one coarse bin are simultaneous/ambiguous and must not be assigned an invented order. The reference graph may restrict which candidate stream pairs are counted, but it does not itself establish that one stream causes another. Compare observed sequence frequency against each stream's own schedule and rate, and distinguish a missing expected step from a sequence still inside its allowed lag window.

Concrete extractor: (1) turn each permitted normal capture into time-stamped per-ID/field **change events** (plus presence/silence observations), filtering candidate counters, checksums, and byte-validity artifacts; (2) estimate candidate directed pair lags `A -> B` from training captures with bounded lag windows and a maximum neighbor count, comparing conditional change probability with within-capture schedule-preserving shifts; (3) compose only supported pairs into a bounded set of chains/forks/returns such as `A -> B -> C -> A`, with fixed maximum span and a deterministic policy for repeated/overlapping matches; (4) record per-pattern frequency per eligible time, lag distributions, completion probability after a prefix, and cross-capture uncertainty; (5) choose template families, support rules, lag bounds, and capacity on source-training/validation captures, then instantiate a target vehicle's ID-specific patterns only from its permitted normal reference. This is a proposed CAN-specific extractor, not an off-the-shelf temporal-motif algorithm: its events are stream changes, while formal temporal-motif work usually counts time-stamped graph edges ([temporal motifs](https://snap.stanford.edu/temporal-motifs/)). Cap candidates and account for the number of tested relations so chance coincidences do not become a large pattern library.

For an initial Graph-Mamba integration, attach pair support/lag and optional pattern-role summaries to the existing bounded reference edges/nodes. At each bin close, a small causal pattern tracker updates only active prefixes and emits `prefix_open`, `completed`, `overdue`, and lag-deviation features for relevant anchors; its bounded state is carried alongside Mamba caches. The GNN can use these as edge/node features and the alert head can receive pooled pattern-surprise scores. Keep the tracker state/compute and source of pattern definitions explicit. Compare this with a separate pattern-score baseline and a simple pair-feature-only Graph-Mamba ablation before adding an end-to-end pattern learner. Zero-shot can use source-trained generic templates on observed stream-change relations, but expected-silence scores require a trusted target normal reference.

**Module boundary and interface.** Implement this first as two components, not a second trainable network: a reference-time `PatternMiner.fit(normal_capture_events, config) -> PatternCatalog` and an online `PatternTracker.step(closed_bin_observations, event_timestamps, catalog, state) -> (pattern_features, pattern_scores, next_state)`. Put the miner/catalog/tracker under `graphids/core/data/discovery/` or a dedicated behavior-context package; keep Graph-Mamba's trainable encoder/heads under `graphids/core/models/`. Extend `VehicleBehaviorContext` with a versioned catalog and provenance. The catalog stores local stream keys, template shape, lag bounds/distribution, mode/support/uncertainty, null-model contrast, and a strict cap on patterns and active prefixes. It contains no query-derived relationships or learned per-target weights. The tracker state holds only bounded active prefixes and deadlines plus optional alert accumulators; reset it at capture boundaries and checkpoint it alongside Mamba state for continuous inference. All feature arrays use stable node/edge/pattern slots and masks, without constructing per-bin graph objects.

At a bin close, update the tracker from the actual ordered event timestamps where available, expire prefixes only after their deadline, and emit per-node/edge overdue/completion/lag features plus a pooled pattern-surprise summary. Feed those features to the same-bin graph readout and current-bin classifier; any forecast of bin `t+1` may use tracker state only through cutoff `t`. Keep an independent pattern score as a diagnostic and baseline; combine it with learned scores only using source-validation weights/thresholds. The first three implementation gates are: (i) miner + standalone tracker against per-ID timeout, (ii) frozen pair features into Graph-Mamba, (iii) bounded chain/return features if (ii) leaves a measured gap. A learned graph-conditioned hazard/completion head is a later ablation, trained on source normal sequences with censored windows; it must not use a target query to refit the catalog. In zero-shot mode, do not instantiate target-ID-specific expected patterns from the query stream: use generic observed-relational features until trusted target normal reference exists.

**Suppression hypothesis and test.** Separate (a) loss of a periodic anchor, detectable from its own elapsed time/count; (b) a context-conditional omission, where B normally follows A during a particular mode, detectable when a high-confidence `A -> B` prefix expires; and (c) timing-preserving masquerade or coordinated suppression, which may need payload/field consistency and may remain unobservable from CAN alone. The pair/pattern tracker adds value only if it detects (b) earlier or with fewer false alarms than a per-ID timeout or the existing next-bin count forecaster. Learn mode-conditional completion probabilities or survival curves from normal reference windows and score at the deadline, not at the moment B first fails to appear; keep incomplete windows right-censored at capture/query boundaries. A learned graph-conditioned hazard head is a later comparator to the explicit tracker. No learned relation guarantees suppression detection when normal modes are unseen, several coupled streams vanish together, or a bus/logging outage removes the evidence.

Evaluate on independently labeled suppression **intervals**, with target ID, start/end, and attack-free normal hours, using matched false alarms/hour, detection delay from interval start, episode recall, and attribution to the missing stream. Since the current CSV event labels cannot label absent frames, first audit whether trustworthy interval annotations exist; otherwise report source-normal controlled deletion probes as synthetic sensitivity experiments, not real-attack recall. Use single-ID deletion, conditional-only deletion, multi-ID deletion, and timing-preserving replacement probes; preserve original timestamps and the surrounding traffic, document what that simulation cannot reproduce about live CAN arbitration/vehicle response, and never tune on held-out target attack labels. The ROAD CAN IDS study distinguishes suspension, which changes timing, from timing-opaque masquerade and discusses the limits of post-processed suspension datasets ([ROAD study](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0296879)). Data-mined temporal invariants in industrial control systems support testing cross-sensor conditional relationships, but their results do not establish this CAN dataset's suppression recall ([ICS invariant study](https://www.sciencedirect.com/science/article/pii/S096706612400323X)).

Pilot this offline on permitted normal reference captures. Count a small, predeclared family of two- and three-node patterns per capture and operating mode, normalize by each stream's activity and the time at risk, then retain recurring patterns with uncertainty and minimum support. Compare against schedule-preserving nulls (for example, within-capture circular shifts that retain each stream's marginal timing while disrupting cross-stream alignment) so shared periodic schedules do not masquerade as a meaningful relation. Hold out normal captures to test recurrence, false alarms, and mode sensitivity. Do not exhaustively enumerate arbitrary subgraphs or store one learned graph per snapshot; compute bounded pattern summaries from the existing snapshot tensors or a streaming counter.

For cross-vehicle comparison, describe each local pattern by relative timing, payload/field-change behavior, node-role probabilities, and local topology, with no reliance on numeric CAN IDs. Softly match pattern distributions with an unmatched option; preserve one-to-many matches because message packing differs across vehicles. The first detector integration is a frozen reference **pattern profile** plus causal per-bin deviations or a small context embedding. This can support a direct graph-pattern anomaly score or feed the shared GNN/Mamba heads. Fit pattern definitions and any shared embedding on source training vehicles only; build a target profile only from its trusted normal reference; never use target query or attack labels to select patterns, matching, weights, or thresholds. In zero-shot mode, use only source-learned generic pattern types and patterns observable by the current cutoff, with no target expected-absence claim.

Test whether patterns add information beyond the current edge-aware GNN and individual ID/field profiles: compare no mined patterns, pair-only summaries, two-/three-node temporal patterns, and shuffled cross-stream timing at matched data access and compute. Report held-out-vehicle detection, false alarms/hour, delay, cross-capture pattern stability, pattern coverage, and construction/inference cost. A graph motif is a **behavioral dependency hypothesis**, not evidence that its nodes correspond to particular physical components. Temporal graphlet and motif-anomaly research motivates this representation, while topological network-alignment research motivates role-based cross-graph comparison ([dynamic graphlets](https://pmc.ncbi.nlm.nih.gov/articles/PMC4765862/), [motif-level anomaly detection](https://ieeexplore.ieee.org/abstract/document/10115014), [graphlet network alignment](https://pmc.ncbi.nlm.nih.gov/articles/PMC2894889/)).

## Joint objectives and scores

The shared Mamba/GNN encoder feeds two logically separate branches.

This is a **two-task, semi-supervised detector**, not a collapse to one binary classification problem. The supervised branch learns patterns of labeled source attacks; the normality branch learns which next-bin behavior is expected from verified-normal source segments and trusted normal reference context. Their scores remain independently available at inference. The current temporal `temporal_gat` is a causal event-attention classifier, and `temporal_vgae` is a recurrent variational **current-event reconstruction** scorer (`graphids/core/models/temporal/{gat,vgae}.py`); the proposed normality task changes reconstruction to causal forecasting so the scored observation was not already in the predictor input. The historical GAT/VGAE implementations remain baselines, not weights or modules transplanted into the replacement.

1. **Supervised classification:** a bin-level head predicts benign versus attack from the current cutoff representation, pooling real nodes with a masked, permutation-invariant readout. Define the bin label from constituent event labels before training; initially use `attack` if any valid event in the bin is labeled attack. For suppression, verify how a no-event interval obtains a label from the recording annotation; absence cannot be labeled from events that never occurred. Report label density and map bin alerts back to physical time for comparison with the event-level baseline. Train this head only on labeled source training data and choose architecture/checkpoints from source validation.
2. **Normal-behavior forecasting:** at cutoff `t`, predict a conditional distribution for observations in bin `t+1` **before those observations are input to the encoder**. Start with per-existing-node presence/count (including zero for anchors), conditional payload-change behavior when a message arrives, and a global new-ID arrival/count head; an ID first seen in `t+1` cannot have had a per-ID forecast at `t`. Include bin duration/exposure in count likelihoods. Start with a simple calibrated count family (Poisson or negative binomial selected on source normal validation dispersion), Bernoulli presence/change terms where appropriate, and masked payload terms; log each proper score and its eligible denominator. If timing-preserving payload attacks remain weak, test a masked valid-byte/bit predictive head rather than assuming change fraction contains enough semantics. This branch is **self-supervised normal-only forecasting**, not unconstrained unsupervised training on all traffic. For the first experiment, train it on windows whose input history and target bin are verified normal; mask boundary crossings, padding, unavailable payload targets, attack intervals, and a declared post-attack recovery interval. This avoids teaching attacks as normal and gives a clean target. Later ablate shorter contamination exclusions. Use labels only to select normal training windows; no attack labels enter the forecasting targets.

**Normality-model choice:** use causal probabilistic forecasting as the primary anomaly mechanism. It makes absence/zero-count bins observable, supports one-pass streaming inference, and gives a clear score aligned to the bin that just closed. A current-bin encoder-decoder reconstruction head sees the observation it scores and can learn to copy it; the existing VGAE remains the reconstruction baseline. Masked-current-bin reconstruction is a legitimate ablation only if the target fields are hidden from *every* path that predicts them and the masking policy is identical at train and test; it adds a different imputation question and cannot by itself score a never-arriving ID without a persistent expected node. Diffusion-based denoising is a later research control only if forecasting demonstrably misses a multimodal normal pattern and an inference-time budget supports sampling; it is not the first online detector. A continuous-time next-event point process is an event-resolution control if physical bins erase short attacks, but it needs an explicit no-event survival term to score suppression. Forecasting and reconstruction can be complementary in other multivariate time-series work ([MTAD-GAT](https://arxiv.org/abs/2009.02040)); diffusion anomaly models are promising but can have materially greater scoring cost ([diffusion study](https://arxiv.org/abs/2311.01452), [fast diffusion alternative](https://arxiv.org/abs/2305.18593)). These are motivations for controlled comparisons, not evidence that adding all objectives helps CAN traffic.

Optimize a weighted sum of classification and normal forecasting losses. Set weights using source training/validation only, and log each loss separately. A normal-only pretraining stage followed by joint training is an optional ablation, not an assumption that the joint loss works automatically. Prevent the classifier from using future-bin targets or forecast residuals computed with future observations at the current cutoff.

Define task separation precisely: classification gradients use labeled source query bins; forecasting gradients use only verified-normal source history/target pairs. Shared encoder weights receive both kinds of gradients, so the **joint encoder is label-informed** even though the forecast targets are self-supervised. Do not describe its anomaly score as the output of a purely unsupervised model. Keep task-specific heads and losses separate, normalize each loss by its eligible units, and record gradient norms/cosine on the shared encoder in a small diagnostic sample. If source validation shows negative transfer, compare loss-weight adjustment, normal-only pretraining followed by joint fitting, and a small task-specific projection or separate encoder; escalate to gradient surgery only if simpler controls fail and its added cost is measured. Joint training has no presumed superiority over two independently trained models.

Predeclare the **coexistence test**: at matched data and compute, compare (a) classifier only, (b) normal forecast only, (c) joint shared encoder with each head scored separately, (d) independent classifier and forecaster with late score fusion, and (e) frozen source-calibrated fusion of the joint heads. For each, report known and unknown attack families, per-vehicle results, false alarms/hour, delay, and which attack episodes are uniquely found by each branch at the same alert budget. A gain in combined AUPRC alone is insufficient if it comes from a changed threshold, leakage, or one branch becoming worse. Keep the normality branch even if its *fusion* weight is zero only when it adds a separately useful open-set or drift capability at an acceptable resource cost; otherwise the full joint replacement claim fails its stated acceptance gate.

Research supports treating complementary objectives as a hypothesis rather than a guarantee. [Open-set supervised anomaly detection](https://arxiv.org/abs/2203.14506) and [open-set graph anomaly detection](https://arxiv.org/abs/2311.06835) study the seen-versus-unseen attack gap; [MOSAD](https://arxiv.org/abs/2310.12294) combines generative/discriminative anomaly objectives. [Gradient Surgery](https://arxiv.org/abs/2001.06782) shows that shared multi-task gradients can interfere. None establishes that classification plus forecasting improves this CAN dataset or that shared weights outperform independent models; the matched coexistence test decides that.

At inference, retain two outputs: `p_attack(t)` from the classifier and `s_anomaly(t)` from the prediction of bin `t` made at `t-1`, scored only after bin `t` has closed. Align both to the close of bin `t`; neither head uses a future bin to classify the present. Evaluate classifier-only, anomaly-only, and a prespecified combination. Fix combination weights using source validation; calibrate score scales and thresholds on source validation or disjoint target **normal** calibration data, declaring which regime is used. Never select weights, thresholds, graph density, context size, or checkpoints with held-out target attack labels. Anomaly score denotes deviation from learned normal behavior, not proof of maliciousness. Report per-node forecast surprise and pooled alert score so a sparse rare-ID anomaly is not hidden by averaging across many normal nodes.

### Slow drift, evidence memory, and calibration

Multiple forecast heads expose distinct channels (count/arrival, payload change, new-ID arrivals), but **head count alone does not create long-horizon detection**. A stateful predictor may eventually follow a slow attack, making its one-bin residual small again. Keep the normal reference immutable and report both (a) next-bin prediction residuals and (b) direct deviations from reference rate, age, and payload-change profiles over declared physical-time horizons. Preserve per-ID signs and identities where useful; pooling an average across all anchors can bury a weak change on one ID. If no trustworthy reference exists, the zero-shot path has a narrower drift claim.

Add a small, separate **alert evidence state** outside Mamba: compare single-bin thresholding with source-selected multiscale rolling summaries and a one-sided cumulative statistic such as `g_t = max(0, g_(t-1) + z_t - k)` on centered/normalized residual evidence. `k`, horizon(s), reset/cooldown, and threshold are fixed from source development data; do not tune them on held-out target attacks. This state can accumulate weak persistent evidence over longer physical time than a training window without expanding Mamba's recurrent state or graph history. Test whether the predictor adapts to injected drift by plotting both its residual and the immutable-reference deviation through the attack. A sequential statistic cannot recover an attack that produces no distinguishable observable signal.

Calibrate the **complete alert policy**, including head combination and evidence accumulation, on chronologically intact normal recordings. Bin scores are correlated; treating millions of bins as independent calibration examples produces overconfident false-alarm claims. Report normal hours, independent recording/session count, observed alerts, false alarms/hour, and uncertainty by vehicle and mode. If a target has only minutes of disjoint normal calibration, it cannot support a precise very-low-false-alarm threshold; keep source-selected thresholds as the primary paired comparison and label target-normal calibration exploratory unless its exposure supports the claimed operating point. Never refresh reference or threshold from live query traffic in the first system: slow malicious drift would contaminate the baseline.

Before final target evaluation, use source-only controlled perturbations with known onset, duration, and magnitude: gradual rate suppression, small periodic timing shift, and payload-bit drift that preserves timing. Include matched normal mode changes. Compare one-bin, multiscale, and cumulative policies at the **same normal-hours false-alarm budget**, with detection delay and minimum detectable drift magnitude. These synthetic probes test sensitivity; they do not replace real held-out attack evidence. Sequential change-detection work motivates cumulative monitoring of weak evidence ([NN-CUSUM](https://arxiv.org/abs/2210.17312), [nonstationary change detection](https://arxiv.org/abs/2110.01581)), while long-context SSM studies warn that recurrent inference alone does not guarantee retention beyond training length ([LongMamba](https://arxiv.org/abs/2504.16053)).

## Training and evaluation protocol

- Train with the reference/query episode and context-withholding protocol above so high-volume recordings do not dominate. Reset Mamba state and reference selection at capture boundaries. Define warm-up and scored masks; warm-up may initialize temporal context but does not contribute to detection metrics. Padding cannot advance state or influence graph messages. Validate both context-present and context-absent paths on source recordings; if source vehicle count permits, rotate an entire source vehicle out for a diagnostic transfer check without touching the final target attacks.
- Choose bin width and sequence length from source training/validation only. Record scored physical duration, event count, attack-containing bins, empty bins, and discarded or padded fractions. Check multiple source-selected bin widths: overly coarse bins dilute brief injections; overly fine bins can create mostly empty sequences and high graph cost. A bin model and an event model have different prediction units; compare common time-based alert metrics as well as their native metrics.
- Report source-validation and held-out-vehicle classification AUPRC, recall at fixed false-positive rate, false alarms per hour, and detection delay/time-to-alert for **both** transfer regimes on the same query captures. Report anomaly-only performance and the combined alert policy separately, including unknown attacks and suppression where labeled data permit. Show paired per-vehicle differences and uncertainty across independent recordings/vehicles, not just pooled event-level confidence intervals.
- Break errors down by short versus sustained attacks, cross-ID lag, payload-changing versus timing-changing attacks, rare/transient IDs, and normal operating modes where the recording metadata support those distinctions. State when a category cannot be identified from available labels or signals.
- Compare against the fixed memory-on `temporal_hybrid` baseline; use Mamba-only, self-path-only, graph-edge-rewired, and context-free ablations to isolate the new components. Include a well-tuned pooled behavioral model as a strong generalization control, plus matched-capacity causal TCN or memory-off temporal control if resources allow. Compare ID-specific or five-branch models only as separate specialization controls, with an explicit unseen-vehicle fallback; they cannot substantiate zero-shot transfer by themselves. Keep source split, target partitions, scored coverage policy, checkpoint rule, and optimizer-step or wall-time budgets explicit.
- Measure **complete uninstrumented training epochs**, not just a Mamba kernel: scored physical time and messages per second, optimizer steps, peak GPU memory, data/context/graph construction time, padding overhead, and streaming p50/p95 latency. The new model earns a speed claim only if the full pipeline improves at comparable detection quality.

## Required checks before interpreting results

1. **Causality:** changing future bins or target labels cannot change earlier outputs; graph edges, normalization, reference profiles, and bin aggregation obey the same rule.
2. **Parallel and streaming equivalence:** compare full-sequence output with event/bin-step inference under declared tolerances, carrying both Mamba SSM and convolution caches. Test capture resets, missing bins, padding, and unknown IDs.
3. **Graph correctness:** permuting local ID indices together with features/context/edges permutes outputs; padding and other vehicles cannot affect a real node. Test edge isolation and the actual neighbor contribution.
4. **Objective masking:** attacked or unavailable next bins never enter the normal forecasting loss. Verify the classification label rule and timestamp alignment of forecast surprise.
5. **Backend and speed:** profiler traces confirm the optimized official Mamba path and no Python loop over time in the training forward pass. Run full forward/backward/optimizer and end-to-end throughput measurements on the deployment GPU.
6. **Node lifecycle:** distinct transient IDs remain distinct, an ID absent from reference is not automatically attacked, silent anchors continue to accumulate age, and slot overflow/eviction cannot silently drop scored events or corrupt another ID's state. Freeze anchor membership throughout an attacked query.
7. **Transfer contract:** target-normal context, normalization, graph construction, and threshold calibration use declared disjoint captures. The zero-shot run cannot accidentally load a target graph/profile or use target labels for model selection.
8. **Episode separation:** query captures never contribute to their own reference; context-withheld episodes use the same generic graph policy as zero-shot inference. A learned reference encoder has shared weights and receives no target attack-test gradients.

## Data and scoring contracts to freeze before implementation

These choices must be written into a versioned schema and exercised on small hand-built recordings before a fit:

| Contract | Required rule and failure case |
|---|---|
| Clock and bins | Specify timestamp units, clock-reset handling, bin origin, half-open interval convention, tie ordering, and final partial-bin policy per recording. Do not join recordings or vehicles through a common absolute clock. Reject non-monotone or ambiguous timestamps rather than silently sorting away evidence. |
| Recording provenance | Group exact duplicates and investigate partial/shared-session overlap before splitting. A source vehicle needs distinct training reference, training query, validation reference, and validation query captures; no validation query builds its own context. Target reference, threshold calibration, and normal test captures must be disjoint at recording/session level. If the available data cannot support a regime, mark it unavailable rather than reuse a capture. |
| Labels | Keep event, interval, and bin labels as distinct fields with provenance. The any-positive-event bin rule applies only where event labels exist. Suppression needs independently annotated start/end intervals and an explicit overlap rule; files with zero positive events do not become positive because of their filename. Unknown or ambiguous intervals stay unscored. |
| Time exposure | Count forecasting likelihood must include bin duration or exposure, especially for partial bins. Empty closed bins are valid observations; padding, unavailable capture time, and gaps from clock failure are not zeros. Record per-bin duration and masks. |
| Node universe | Anchors are fixed from trusted reference. A transient slot has an ID key, first-seen cutoff, retention horizon, and reset semantics. Define whether an evicted ID may re-enter cold and how scored events remain represented during overflow. An aggregate overflow counter can preserve evidence, but cannot stand in for per-ID forecasts; report this coverage gap. |
| Payload | Preserve byte availability and original raw values. Treat unavailable DLC/validity as unknown, not as valid zeros. For per-ID payload forecasting, a next-bin with no message has no payload target; repeated latest payload is an input state, not a new observation. |
| Prediction alignment | The classifier for bin `t` may read the closed bin `t`; the forecast made at `t-1` is scored against bin `t` only after `t` closes. First-bin anomaly coverage requires an explicit warm-up predecessor; terminal forecasts are not scored. Keep the two eligible-denominator counts separate. |
| Forecast training | Define verified-normal history and target masks, including mixed attack recordings, uncertain attack boundaries, and post-attack recovery. Count all excluded time and events. Classification may train on attacks while forecast loss is masked; report whether shared encoder gradients from attack examples affect the normality branch and ablate separate or stopped-gradient encoders if interference appears. |
| Alert policy | Choose score aggregation across IDs, score normalization, threshold, minimum persistence, cooldown, and episode reset on source validation or a declared disjoint normal calibration set. Account for the changing number of nodes and bins/hour. Report candidate bin scores and final alerts; compute false alarms/hour from elapsed normal test time, not event count. |
| Context lifecycle | Bind each query to an immutable context digest and authorized capture list. Freeze profiles, graph, normalization, anchor membership, and thresholds for the whole query. Define a separate trusted refresh operation with a new digest and a new evaluation episode; never adapt from live unlabeled traffic during the first replacement. |

The first anomaly version should use a complete likelihood or proper score for each modeled target and log its terms. For a count head, include explicit zero-count probability; for a payload-change head, score only when a payload observation exists. Calibrate component scales on authorized normal data before summing them. A new-ID global head must be scored against actual arrivals and must not assign probability to a target ID learned from future query traffic. If a head cannot provide a defensible score under these masks, omit that component from the first anomaly score and state the resulting detection gap.

Before promising a graph benefit, test whether reference edges encode stable relationships after conditioning on shared rate and operating mode. Use a matched self-only and shuffled-edge control with the same node features and trainable parameter budget. For missing anchors, preserve the graph node and age/count features, but do not let static edge messages be mistaken for an observed transmission. Track edge construction and query-time transient-edge computation separately in the speed budget.

## Implementation sequence

1. Freeze and record existing cross-vehicle baseline manifests, checkpoints, coverage, and timing. Audit reference-to-query ID coverage, attack/transient load, suppression annotations, bin widths, and graph construction feasibility. Choose `K_max`, `M`, and bin-label contract from source data only.
2. Resolve the isolated Mamba backend gate on Ascend A100 or Cardinal H100 before building the snapshot pipeline; use the same device model for the candidate and matched baseline. Test sequence forward/backward, optimizer, streaming, and cache semantics. Stop the named replacement if its required hardware cannot support the optimized backend.
3. Run the source-only snapshot workload census and worst-geometry preflight on the selected GPU in the batching contract above. Build causal snapshot data, bounded eager batching, reference artifacts, two-tier node lifecycle, and provenance/mask tests. Add a repository-native `vehicle_graph_mamba_joint` model and configuration; keep it separate from `temporal_hybrid`. Integrate the verified backend and check live-segment packing, causality, and streaming equivalence before adding the graph.
4. Add the sparse same-time GNN, both heads, and the source-vehicle reference/query episode sampler with a context-withheld zero-shot path. Test objective masks, episode separation, graph isolation, and source validation. Begin with deterministic profiles; add a shared learned reference encoder only after its ablation is justified.
5. Run pooled behavior-only, Mamba-only, fixed-profile conditioning, optional learned-reference conditioning, graph/context, classifier-only, anomaly-only, and joint comparisons. Check cross-ID lag, event-resolution, and operating-mode errors. If those checks show a concrete gap, compare observation-only GNN `->` Mamba `->` GNN, alternating layers, event-level, or TCN controls at matched inputs, heads, and work. Keep per-vehicle experts and target adapters as later controls. Select using source validation, then run the frozen checkpoint on each held-out query capture in both zero-shot and reference-conditioned modes. Keep source-threshold paired results primary; report target-normal calibration separately. Audit persistent/transient coverage, unknown-ID false alarms, and context-build cost alongside detection metrics.

6. After the single-corpus model passes its architecture gates, audit compatibility and cross-corpus overlap, then pilot two CAN dataset families with hierarchical sampling. Compare specialists, full sharing, and limited schema specialization; run the transfer matrix and source-selected dataset-holdout protocol above. Broader domains require their own node/edge/feature/target contracts and a separately named variant.

The initial architecture succeeds only if the **full joint model** provides useful classification and anomaly detection on held-out vehicles while its end-to-end training cost and memory are acceptable. A fast Mamba scan alone, or an unmeasured GNN layer, does not establish that result.

## Open questions

### Resolve from source data and implementation checks before the first fit

1. What physical bin widths preserve short attacks while keeping empty-bin and graph costs manageable? What event-to-bin rule correctly labels suppression intervals with no events?
2. How many distinct IDs occur in authorized normal reference unions, and what normal query and attack/transient load must `K_max` and `M` cover? What deterministic transient eviction policy preserves distinct IDs under flooding?
3. Are DLC or equivalent valid-byte indicators available in each recording source? Which payload targets must be masked when their validity is unknown?
4. Which normal recordings can be reserved separately for target reference construction, threshold calibration, and normal testing without breaking the existing cross-vehicle split contract?
5. Does a pinned official Mamba backend provide the intended parallel forward/backward path on the selected A100 or H100 within memory limits? What sequence, chunk, and streaming-cache semantics does that exact version support?
6. How many genuinely independent vehicles and recordings support the paired transfer study after duplicate/session grouping? Can every target vehicle supply reference, calibration, and normal-test captures without using attack-test information? If not, which co-primary comparison can still be made honestly with source-only thresholds?
7. Which attack families have reliable interval boundaries, and which are only event-labeled? What minimum attack duration and bin width permit a fair alert-time comparison with the event-level baseline?
8. What baseline-derived quality, false-alarm, latency, peak-memory, and training-cost bounds define a successful full replacement? Freeze these from source validation before any target attack-test review.

### Answer with source-validation ablations

9. Does normal-reference conditioning improve transfer over the paired zero-shot path and a well-tuned pooled behavioral model, and how much trusted normal reference is needed? Does training with context withheld preserve both modes' quality?
10. Does the GNN add detection value beyond Mamba, extra parameters, and a self-path readout? Which graph edges or lag features matter, and do fixed normal edges remain useful across operating modes?
11. How often do benign IDs absent from the trusted reference trigger false alerts, and does transient eviction hide attacks? If a future reference exceeds `K_max`, does a source-validated capacity policy preserve the rare IDs needed for detection?
12. Do classification and normal-only forecasting improve one another or compete for encoder capacity? Are classifier-only, anomaly-only, or a source-calibrated combination best under the chosen false-alarm constraint?
13. Are errors concentrated in cross-ID lag, brief event ordering, timing-preserving payload changes, or normal mode shifts? If so, does observation-only GNN `->` Mamba `->` GNN, finer/event-level input, or a simpler TCN control resolve the specific gap at acceptable full-fit cost?
14. At a fixed normal-hours false-alarm budget, do immutable-reference deviations plus cumulative evidence detect weak persistent changes earlier than one-bin scores? Does continuous Mamba state follow slow drift and shrink forecast residuals? How sensitive is the result to normal operating-mode changes and limited calibration exposure?
15. Do source-learned behavioral role features improve held-out-vehicle transfer beyond raw timing/payload/reference features, or do they merely cluster recording modes and attack families? Compare whole-ID profiles, candidate field roles, and shuffled roles under the same target-access and compute budget; measure match stability across disjoint normal captures and preserve an unmatched option. Are any decoded physical signals independently verified well enough to support a separate physical-consistency experiment?
16. Do recurring two-/three-stream temporal patterns add held-out-vehicle detection value beyond pairwise reference edges and individual stream profiles? Are the patterns stable across normal captures and operating modes after activity-normalized, schedule-preserving-null checks, and does cross-vehicle soft matching help more than generic pattern statistics at acceptable cost?
17. For independently interval-labeled or clearly marked synthetic suppression episodes, do conditional missing-step scores improve recall or delay over per-ID timeouts and next-bin count forecasting at the same normal-hours false-alarm rate? Which cases remain unobservable because the context trigger, dependent streams, or recording itself disappear?

Keep the final held-out target attack labels closed while answering these questions. Record decisions, source evidence, and remaining uncertainty in the experiment report before promoting any architecture variant.
